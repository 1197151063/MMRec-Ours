# 完整共同物品群 + item语义桥：短路径连通性研究

## 研究目标与预先固定的对照

取消 user top-20 截断，保留所有训练 user-item 边。
物品连接所有交互用户，对应物品诱导的超边，不展开成稠密用户团。
仅测试结构，不训练模型、不加user loss、不使用验证/测试边构图。

默认7组：

1. full_shared_items：原始训练 UI 二分图。
2. semantic_k5：额外加入 item 正余弦 top-5，按双向并集无向化。
3. semantic_k10：额外加入 item 正余弦 top-10，按双向并集无向化。
4–7. 两种K各自两个度数保持的随机重连图，保留原UI图不动。

图像和文本分别归一化后拼接并再归一化，静态语义边不包含自环。
无向化后的物品度数不一定等于K。
随机双边交换逐节点保持II度数及边数，目标成功交换5×原无向边数。
报告交换次数及原边保留率；有限次交换不保证在所有同度数图上均匀采样。
每个随机图均独立重新从对应语义图开始。

## 路径的定义

这里 hop 指实际二分/增强图上的一条边，不是投影后的user图步数：

- 2条：U–I–U，等价于完整共同物品用户图中的直接连接。
- 3条：可通过 U–I–I–U 加入语义桥。
- 4条：还允许 U–I–U–I–U 或 U–I–I–I–U。

结果报告“最多h条边”，包含更短的路径。排除用户自身。
2-hop 结果应在全部图上保持一致，因为所有组保留完全相同的UI边。
不用稠密全对最短路：对用户采样分块做精确布尔可达性计算。

## 用户对与评估

默认从训练集活跃用户均匀无放回采样2048个anchor，各组完全共用：

- ID精确相差+1、+4、+16、+64、+256的有效用户对。
- 随机其他用户（排除自身和该近编号目标）。
- 目标用户度数匹配对照；精确度数池无候选时用最近度数，报告回退数。

仅评估阶段读ID距离；构图、语义排序、重连均不使用它。
2/3/4-hop各自输出：近编号/随机/度数匹配可达率、近编号减匹配的绝对差、比值。
同时报告每个anchor可达用户数量及占比、全图最大用户连通分量、每类用户对是否同分量。
这些是样本描述统计，不包含独立样本置信区间；两次重连仅作机制对照，不能当显著性检验。

不要只看“近编号可达率”上涨。若对照用户也接近100%，意味着图过密或路径过长；
不能据此宣称恢复了编号关联。语义桥需要与相同II度数的随机图比较。
不以ID可达率选择推荐模型超参数或挑选随机种子。

## 输出及资源

- report.json：每组完成后更新，可部分存在；以status.json=complete为完成依据。
- status.json：running / failed / complete。
- query_pairs.npz：固定的采样用户对，便于复核。
- 每个语义/重连图的 *_item_graph.npz：布尔无向item图，UI边从同一训练集读取。
- 输入与源码hash用于追踪版本。不保存模型。

CPU即可。默认block=32、anchors=2048；路径扩展可能变密，程序每256个anchor报告进度。
无需创建NxN稠密全对矩阵，但更大的block/anchor数会增加资源开销。

## 服务器运行与查看日志

在项目根目录，输出目录须不存在：

```bash
nohup python -u experiments/research_user_connectivity.py \
  --data-path /root/autodl-tmp/MMRec-Ours/data --dataset baby \
  --output night_runs/baby-connectivity-1 \
  > baby-connectivity-1.log 2>&1 &
tail -n 50 -f baby-connectivity-1.log
```

若需要降低内存，改用 --block 8 并使用新的输出目录；不会改变定义或采样用户对。
运行结束返回 report.json、status.json、外层日志。
